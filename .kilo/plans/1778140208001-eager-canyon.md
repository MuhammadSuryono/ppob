# PPOB Database Migrations Plan

## Objective
Generate SQL migration files for the PPOB microservices database schema based on the documented models and architecture.

## Current Status
- Docker Compose references `./migrations` folder but it doesn't exist
- Database schema is fully documented in `v1/docs/Database Schema for PPOB Mobile Application.md`
- Go models exist in service directories but need SQL schema

## Migration Files to Create

### 001_initial_schema.sql
Core tables required for all services:
- `users` - User accounts with phone, name, password/PIN hashes
- `roles` - System roles (Mitra, Staff, Admin)
- `user_roles` - Many-to-many user-role assignments
- `wallets` - Wallet management with balance tracking
- `wallet_events` - Event-sourced balance changes
- `transactions` - PPOB transaction records
- `products` - Digital products catalog
- `categories` - Product categorization

### 002_otp_and_device_security.sql
Security-related tables:
- `otp_codes` - OTP verification codes
- `device_fingerprints` - Device trust tracking
- `audit_logs` - System audit trail

### 003_transaction_support.sql
Transaction processing support:
- `daily_limits` - Per-user daily transaction limits
- `idempotency_keys` - Duplicate request prevention
- `transaction_status_events` - Transaction state history

### 004_margin_settings.sql
Staff margin configuration:
- `staff_global_margin_settings` - Default margin per staff
- `staff_product_margin_overrides` - Per-product margin overrides

### 005_integration_tables.sql
External integration support:
- `integration_logs` - Digiflazz API call logs
- `provider_configs` - Provider configurations
- `postpaid_inquiries` - Postpaid bill inquiry cache
- `compensation_jobs` - Failed operation retry queue

### 006_system_configuration.sql
System settings:
- `system_settings` - Global key-value configuration

## Implementation Steps

1. **Create migrations directory**: `v1/migrations/`

2. **Generate 001_initial_schema.sql**:
   - Create tables in dependency order (users → roles → wallets → products → transactions)
   - Include all constraints, indexes, and checks
   - Add triggers for auto-updating timestamps

3. **Generate 002_otp_and_device_security.sql**:
   - OTP code table with expiration handling
   - Device fingerprint table for fraud detection
   - Audit log table with trace ID support

4. **Generate 003_transaction_support.sql**:
   - Daily limits with atomic increment support
   - Idempotency key table with TTL
   - Transaction status events

5. **Generate 004_margin_settings.sql**:
   - Staff margin settings split into two tables
   - Foreign key constraints to users and products

6. **Generate 005_integration_tables.sql**:
   - Integration logs for Digiflazz API tracking
   - Provider configuration table
   - Postpaid inquiries cache
   - Compensation job queue

7. **Generate 006_system_configuration.sql**:
   - System settings with seed data

## Key Design Decisions

1. **UUID Primary Keys**: Using `gen_random_uuid()` for all tables
2. **Time Zone**: All timestamps in UTC, application handles conversion
3. **Decimal Precision**: 18,2 for money, 5,2 for margins
4. **Soft Deletes**: `deleted_at` column on users table
5. **JSONB for Metadata**: Flexible schema for additional data

## Down Migration Strategy
Each migration file will include:
```sql
-- +goose Down
DROP TABLE IF EXISTS table_name CASCADE;
```

## Testing Plan
1. Run migrations against fresh PostgreSQL instance
2. Verify all tables created with correct constraints
3. Test down migrations for rollback
4. Validate with service startup
